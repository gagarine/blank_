# Native acceptance

## Architecture and interface assessment

The macOS 27 SDK's attributed `TextEditor` accepts `Binding<AttributedString>` and optional `Binding<AttributedTextSelection>` (macOS 26+), including typing attributes and transformations. NSTextView is chosen because this editor needs pre-edit delegates, marked-text hooks, caret rectangles, custom clipboard handling and block mouse tracking. The deployment target is macOS 26; compatibility with older macOS is not a reason for this choice.

`NSTextView(usingTextLayoutManager: false)` explicitly selects TextKit 1 at creation for both Write and Source. This is intentional: integrated `NSTextTable` editing is a product requirement. Native geometry uses character rectangles, insertion-position hit testing and NSLayoutManager. There is no runtime engine switch during typing. Apple documents [explicit TextKit 1 initialization for unsupported features](https://developer.apple.com/videos/play/wwdc2022/10090/).

Tables are native `NSTextTable` / `NSTextTableBlock` paragraphs in the same text storage as surrounding prose. There are no table overlay controls, per-cell field editors or fixed row heights. Cell projections retain local inline structure and map UTF-16 selections to canonical UTF-8 spans; cells have synthetic native paragraph terminators, which never replace source delimiters. Table edits commit localized source changes into shared Write/Source history. Return creates a paragraph within a cell; Tab/Shift-Tab navigates cells, and final-cell Tab adds a row. Selecting a whole table preserves its complete source when copied; selections across cells retain table delimiters during edits. Native bold/italic faces and links render within cells. The cell slash menu currently offers Paragraph, Link, Footnote, Citation, Label and Cross-reference. Heading/list/quote conversion, nested tables, figures and equations are excluded until their cell rendering/editing is supported. Choosing Table outside a cell inserts an empty 2×2 table and focuses its first cell without a sizing dialog. The block menu retains dimensions editing. Generated or complex tables remain source blocks.

Figures still reserve native attachment geometry and mount visible AppKit image/caption controls as text-view subviews. Offscreen figure controls are removed. Figure captions and alternative-text editing remain separate from integrated table paragraphs.

TextKit 2 was evaluated before this decision. On macOS 27.0.1, a 2×2 `NSTextTableBlock` fixture laid out correctly but an initially TextKit 2 view switched to TextKit 1. The historical probe remains [scripts/text-table-probe.swift](../scripts/text-table-probe.swift); compile with `swiftc -module-cache-path .build/module-cache scripts/text-table-probe.swift -o /tmp/blank-text-table-probe` and run in a desktop session. A separate NSTableView implementation retained TextKit 2 but required separate cell controls. It has been removed in favor of integrated native text tables. [Edmund](https://github.com/I7T5/Edmund/blob/main/Sources/EdmundCore/Rendering/EditorTextView%2BTableRendering.swift) uses custom TextKit 2 table decoration; that approach was researched but is not used here.

The toolbar is a standard customizable NSToolbar with unified window layout and macOS 27 tab-role view selection. Full-size content and a transparent titlebar let scrolling content extend beneath it; native scrolling supplies its automatic edge treatment. No custom toolbar glass or white titlebar background is drawn. Controls follow system appearance by default. Write retains native spelling/substitution preferences, including changes made through native controls; Source disables prose substitutions and restores those preferences when returning to Write. Standard Services and represented-document title behavior are included. The editor page, text, native tables, figure captions and Source syntax colors follow the effective macOS appearance by default. Settings retains an optional custom page/text palette; table cells share that palette even in a window with a different appearance. Earlier saved default RGB palettes migrate to system colors; explicit custom palettes remain available. Paragraphs use native font metrics, moderate line spacing and spacing after paragraphs, including their terminators. Empty paragraphs have a visible gap without inflating the caret. Soft line breaks use native line separators within the paragraph and map to Typst linebreak syntax.

Apple references: [TextKit](https://developer.apple.com/documentation/appkit/textkit), [NSTextView](https://developer.apple.com/documentation/appkit/nstextview), [AppKit's new design](https://developer.apple.com/videos/play/wwdc2025/310/), [transparent titlebars](https://developer.apple.com/documentation/appkit/nswindow/titlebarappearstransparent), [adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass). The system controls adapt to accessibility transparency/motion preferences; those configurations still need visual acceptance.

Model-driven text storage changes use AppKit’s pre-edit and `didChangeText()` notifications before final layout/selection. Native insertion-point state is restarted after that selection and again on the next main-loop turn, after AppKit completes its key event bookkeeping. This fixes the reproduced case where Return after the tutorial title left the caret invisible until arrow navigation. There is no custom blink timer or custom caret drawing. Active-app checks verify selection mapping, focus, insertion-point eligibility and body-sized empty-paragraph geometry, plus tutorial undo/redo and Unicode insertion. Real keyboard inspection confirmed a visible native caret immediately after the tutorial title Return. No insertion-point drawing override is used.

Native window checks exercise Aqua and Dark Aqua page/table colors. A custom white page with black ink keeps black table text in a dark window. A disposable NSTextTable document visibly confirmed grid placement, real bold/italic text, mouse caret placement, native selection, Tab navigation, paragraph growth and a visible caret after Return. Clipboard insertion preserved emoji in the correct cell, and Source showed its exact Typst content. The accessibility tree now contains table text as part of the document text; VoiceOver table navigation still requires acceptance.

- Native NSTextTable checks verify engine selection, row/column identity and geometry, light/dark colors, Unicode typing, inline formatting/replacement, clipboard, paragraphs within cells, synthetic composition, growing cell geometry, shared Undo/Redo, Tab/Shift-Tab and valid row creation/focus. - The official compiler produces PDF/source maps. Errors retain the prior PDF; export requested during compilation includes a native imported figure and caption. - Disposable project checks pass include/import loading, exact UTF-8 saves, overlap rejection, deletion/recovery, rename/history retention, Save As dependencies/configuration and preflight collision rejection, nested-chapter asset paths, live includes, directory creation events and chapter undo/redo. Imports remain outside the expanded manuscript; Save As ignores commented asset examples and accepts project configuration with non-string values.

The CLT environment lacks XCTest; `BlankCoreChecks` exercises the production model directly. The SDK's SwiftUI State macro lacks a CLT plugin; `NativeState` aliases the stable property wrapper.

## Native inspection

The isolated native app was inspected through real macOS keyboard input. Cmd-1/Cmd-2 changed the toolbar's selected tab and restored editor focus. Exact Source insertion followed by Write displayed Japanese, emoji, heading sizes and real bold/italic faces. The ordinary keyboard automation tool did not inject Japanese characters through `typeText`; clipboard insertion and synthetic marked-text checks succeeded. This does not validate a real IME candidate-panel session.

Native tutorial scrolling visibly placed text behind the glass controls, with the scrollbar at the viewport edge. A fresh document confirmed the corrected caret height and paragraph rhythm. Real slash filtering and Down/Return choice passed. Manual inspection found a collapsed popover; constraining its hosted root height fixes the missing visible rows. Real Return/Shift-Return and a pointer drag were checked on 2026-10-05 in a disposable app: Source retained paragraph breaks and Typst linebreak syntax, and dropping reordered the canonical blocks. Native drag snapshots verify a translucent preview and one centered line. A gutter-only bitmap assertion verifies that the handle dots are actually painted; the text-view drawing context is restored before gutter overlays so TextKit clipping cannot hide them. Handles, lines and list markers use the editor’s effective ink color for contrast. Native handlers check open-hand hover, immediate closed-hand press, drop cursor restoration and sidebar pin state. The running rebuilt app visibly showed the gutter handle, opened its compact block menu with the current type excluded, and passed toolbar pin/header unpin through accessibility actions. Physical pointer-only hover traversal still needs broader coverage. Pinning clears transient hover; one expanding hover region keeps the unpinned panel stable when moving from the edge into its contents. The pin has a native 24-point hit target and an explicit accessibility label. VoiceOver, bidirectional input and expanded object/long-document drags still require acceptance. Track remaining functionality separately in [parity.md](parity.md).

## Resource measurements

Measured using the production `--measure` harness in a release build. These are short local observations, not targets or a whole-thesis benchmark. RSS is the editor process only; compiler process memory is excluded.

| Measurement | Observed |
|---|---|
| Empty editor, five seconds idle | 0.006 CPU seconds, 0.12% of one core; 72.6 MiB RSS |
| 100 paragraphs / 9,988 source bytes | Load 20.7 ms; local edit median 0.8 ms, max 1.3 ms |
| 1,000 paragraphs / 100,888 source bytes | Load 91.4 ms; local edit median 2.7 ms, max 3.0 ms; 114.6 MiB RSS |
| 1,000-paragraph native key transaction, ten edits | Median 9.7 ms, max 12.9 ms; 128.0 MiB RSS |

These measurements were taken on 2026-10-04, before the subsequent Return/drag corrections. They include the earlier toolbar/paragraph/statistics, live-include and native input-preference refinements. Different runs have different font/window warm-up and resident-memory states; these values are observations, not guaranteed limits. The key metric includes the synchronous native edit/model/attribute update; it excludes complete display presentation and physical key-to-screen latency. Edits in the model measurement retained ten bytes of changed text in history. Full structural parsing, Source styling and undo reprojection still scale with document length.

The compiler protocol check observed 0.705 s cold for the two-page tutorial and 0.160 s warm for a smaller edited fixture; these exclude PDFKit presentation. Representative thesis files, long sessions, memory pressure, image-heavy projects and total compiler/editor RSS remain to be measured. To reproduce the editor harness, launch the built app with `--measure` and a disposable `BLANK_DATA_DIR`.

A repeat release measurement on 2026-10-05 after the caret/appearance corrections observed 0.003 CPU seconds over 5.001 seconds idle (0.06% of one core), 76.0 MiB idle RSS, and a 1,000-paragraph native key transaction median of 13.4 ms (maximum 18.1 ms, 139.5 MiB RSS). The same short-run and editor-only limits apply; these are observations from one run.

After explicit TextKit 1 adoption on 2026-10-05, one release run measured 0.01% of one core over five seconds idle, 95.9 MiB idle RSS, and a 1,000-paragraph native key transaction median of 13.3 ms (maximum 25.4 ms, 151.4 MiB RSS). A 100-row / 200-cell native table measured 49.7 ms median and 51.0 ms maximum per key transaction, with 175.0 MiB cumulative editor RSS after the preceding fixtures. Large-table editing still needs optimization; these are synchronous transactions, not measured physical key-to-screen latency. The compiler process is excluded.

## Final review and build checks

An independent code review on 2026-10-05 found and prompted fixes for mid-paragraph structured paste, invalid UTF-8/new-file save conflicts, nested-entry Save As references, discarded-local conflict recovery, Quit during native composition, and slash escaping in generated Typst strings. Regression checks exercise the affected production paths, including official compilation of generated figure and relocated include/read paths. Choosing the disk version writes a separate conflict snapshot synchronously; later rolling recovery cannot replace it. Real IME candidate panels and VoiceOver remain unverified.

Build scripts now build the parser before model checks, download locked dependencies by default, share one pinned Rust toolchain and clean disposable acceptance data. Both debug/release configurations use one app bundle. SDK selection guards the macOS 27 toolbar property at compile time and runtime. The GitHub workflow checks SDK/toolchain environments on macOS 26 and Xcode 27 and uploads ad-hoc signed app archives. Local macOS 26 SDK checks run on the macOS 27 host; they do not establish macOS 26 runtime acceptance.
